## Why I built it

ZTNET makes a ZeroTier network easy to administer, but gives its other members no view of it. Netmap is a page
every member can open from any device inside the network: it says in plain words whether the device is connected
and how, directly or through a relay ("it works, just slower"), with latency, addresses and client versions one
tap away. It needs no account and cannot change the network.

Version 0.1.0 is a rewrite from scratch: a Flutter web app in Material 3 Expressive, a new map and a new server.

## The map

The map is the home page: a constellation with the hub in the middle, the viewer's own devices highlighted and
one island for every person with two or more devices. Every device is a circle with the colour, icon and word of
its link, and every line is drawn as direct, through a relay or one-way. Beside it, a panel says how you are
connected, copies your address, counts who is online, lists the services with an Open button and shows the
latest activity. Selecting a device explains it in plain words, with the technical details folded underneath.

## Devices and history

- **Latency that means something**: median, 95th percentile and jitter, and each device compared with itself
  the week before.
- **Configured, received, applied**: DNS, routes and addresses followed from the controller to the hub, so you
  see where the chain breaks.
- **What changed**: disconnections, path changes and latency spikes. Three devices dropping in the same poll are
  one incident, usually the hub's connection, not three.
- **24-hour availability** in 24-minute cells, 30 days of traffic, and who uses the network most. Until the
  history fills up, empty slots stay empty: the page never shows data it doesn't have.
- **Services directory**: what you can reach inside the network, how to connect, and whether it answers right
  now, each with its own icon, fetched by the server so the browser never contacts the service.

## How it works

A TypeScript server polls ZTNET's REST API for the members and the network configuration, and the local ZeroTier
service for latency, path types, client versions and what reached the hub. Each poll is compared with the
previous one to produce events, and a new snapshot is pushed to every open page over Server-Sent Events. The
server is a single bundle with no `node_modules`, and the API contract is written once in TypeScript and mirrored
in Dart.

The app is Flutter for the web, built to WebAssembly where the browser supports it and to JavaScript elsewhere,
with the engine, fonts and icons bundled: nothing comes from a CDN, so it works with no internet access. Every
state has a colour, an icon and a word, never colour alone, with AA contrast in both themes, keyboard and screen
reader support and reduced motion respected. It speaks English and Italian, on a desktop or a phone, and
golden tests draw the screenshots on this page.

It runs as a container sharing the ZeroTier container's network: it is reachable only from inside the ZeroTier
network and publishes no port on the host. History survives restarts in a file written atomically.

## Privacy

Everyone in the network can open the page, so the **ZTNET token** stays on the server, devices' **public IP
addresses** are used only server-side to tell LAN from internet and are never sent to the browser, and the page
is **read-only**: authorizing members stays in ZTNET.
