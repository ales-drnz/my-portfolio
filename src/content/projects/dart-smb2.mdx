## What it is

A Dart client for SMB2 and SMB3 file shares (the protocol used by Windows shares and most home NAS devices).
It's a plain Dart package with no Flutter plugin: a build hook bundles libsmb2 for Android, iOS, Linux, macOS
and Windows, checked against pinned SHA-256s, so the same API works in a Flutter app, a command-line tool or
a server.

## Architecture

`Smb2Pool` is the entry point. It runs a few worker isolates, each with its own connection to the share and
its own `Smb2Client`, the synchronous client over libsmb2. Your code calls the pool from any isolate; each
call goes to the least busy worker, so the UI isolate never waits on the network.

<Image src={architecture} alt="Architecture: your code calls Smb2Pool, which sends each request to one of its worker isolates; each worker runs an Smb2Client over its own libsmb2 context" widths={[800, 1600]} sizes="(min-width: 768px) 720px, 100vw" />

```dart
final pool = await Smb2Pool.connect(
  host: 'nas.local',
  share: 'Music',
  user: 'alice',
  password: 'secret',
  workers: 4,
);

for (final entry in await pool.listDirectory('')) {
  print('${entry.name}  ${entry.isDirectory ? 'dir' : '${entry.size} B'}');
}

final written = await pool.downloadToFile(
  'Album/01 - Intro.flac',
  '/storage/music/01 - Intro.flac',
  onProgress: (received, total) => print('${received * 100 ~/ total}%'),
);
```

## Streaming and downloads

`streamFile()` keeps one file handle open and reads the next chunk while your code handles the current one,
so at most two chunks are in memory. `downloadToFile()` writes at the pace the disk takes, into a temporary
file that is renamed to the destination only once the download is complete. Reads land in native buffers
that reach your isolate without a copy.

<Image src={streaming} alt="Streaming: the worker reads the next chunk while your isolate writes the current one" widths={[800, 1600]} sizes="(min-width: 768px) 720px, 100vw" />

## Reconnecting

When a connection drops, the pool reconnects once for every caller that was waiting on it, repeats the call
when that is safe and reopens open files. Calls that change the share (`mkdir`, `rmdir`, `deleteFile`,
`rename`) reconnect but aren't tried a second time.

<Image src={reconnect} alt="Reconnect: a worker loses its connection, the pool spawns a new worker and repeats the call" widths={[800, 1600]} sizes="(min-width: 768px) 720px, 100vw" />

## Also included

- **Cancellation**: every call on a connected pool takes an `Smb2CancelToken`, the same as in dart_plex and
  dart_jellyfin.
- **Typed errors**: every failure is an `Smb2Exception` classified from the server's NT status: auth, not
  found, network, transient or cancelled.
- **SMB3 security**: NTLM sign-in, encryption and signing, and the dialect you choose, up to SMB 3.1.1.
- **Files and directories**: listings with metadata, byte ranges, handles, writes, renames, timestamps,
  share space and share enumeration.

## Native builds

The binaries come from [libsmb2-scripts](https://github.com/ales-drnz/libsmb2-scripts): a pinned upstream
libsmb2 commit with a small set of patches, cross-compiled for Android, iOS, macOS, Windows and Linux on
multiple architectures. The same repository is the corresponding source of the LGPL-2.1 binaries the
package ships.
