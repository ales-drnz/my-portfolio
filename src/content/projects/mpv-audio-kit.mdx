## Why I built it

Many Flutter audio libraries are built on an old version of mpv, or hide its audio processing. mpv_audio_kit
exposes the whole engine through a typed Dart API, without blocking the UI, for apps that play a media library:

- **Jellyfin**: direct or transcoded streams, and transcoded HLS stays seekable while the server converts.
- **Plex**: tracks and playlists over HLS or DASH; each entry asks the server for its stream only when it opens,
  so a long queue starts at once.
- **Samba**: play straight from a NAS or any network share over SMB2 and SMB3.

The project is split across three repositories:

- **mpv_audio_kit**: the Dart and Flutter package, published on pub.dev.
- **[libmpv-scripts](https://github.com/ales-drnz/libmpv-scripts)**: mpv and FFmpeg built without video, with
  the patches the package relies on (waveform, loudness scan, audio taps, live PCM), for every platform it runs
  on, from a terminal menu written in Go.
- **[MPV Studio](/projects/mpv-studio)**: the reference app built on the package, which also
  [runs in the browser](https://ales-drnz.github.io/mpv_studio/).

## Getting started

```yaml
dependencies:
  mpv_audio_kit: ^0.8.0
```

```dart
void main() {
  WidgetsFlutterBinding.ensureInitialized();
  MpvAudioKit.ensureInitialized();
  runApp(const MyApp());
}

// then, in the app
final player = Player();
await player.open(Media('https://example.com/audio.flac'));
await player.play();
player.stream.position.listen((position) => print(position));
await player.dispose(); // when you are done
```

`player.state` holds the current values and `player.stream` sends each change.

## Architecture

The `Player` lives on the main isolate and calls libmpv without waiting on it. A background isolate blocks on
`mpv_wait_event` and brings state back, so slow network streams and heavy filter graphs never block the UI. On the
web the module wakes the player on the main thread instead.

<Image src={architecture} alt="Architecture: Your UI and the Player on the main isolate, the event isolate, libmpv on native threads with mpv 0.42 and FFmpeg, and the platform plugin bridging to the system media controls" widths={[800, 1600]} sizes="(min-width: 768px) 720px, 100vw" />

The media session is driven from Dart too: the media notification on Android, Now Playing on Apple, MPRIS on
Linux, the media controls on Windows and AVSession on HarmonyOS, everywhere but Tizen and webOS. On Android and
HarmonyOS it also keeps the app playing in the background.

## Twelve platforms

Android, iOS, macOS, Windows and Linux; Android TV, tvOS, Tizen and webOS on TVs; Wear OS on watches; HarmonyOS;
and the browser. A Dart build hook downloads the libmpv build for each native target from the project's releases
and checks it against a pinned SHA-256. The toolchains that run no build hook get theirs another way: Swift
Package Manager on tvOS, CMake on webOS, and the web module ships inside the package.

## In the browser

On the web, mpv and FFmpeg run as one WebAssembly module with libmpv's threads in web workers, network reads go
through `fetch`, and the sound plays from an AudioWorklet fed through a ring in shared memory. The page has to be
cross-origin isolated, and a user gesture starts the audio. [MPV Studio](https://ales-drnz.github.io/mpv_studio/)
runs this way, the whole app in a browser tab.

<Image src={web} alt="The web pipeline: the Player on the main thread, libmpv.wasm and a network thread in web workers, PCM through shared memory to an AudioWorklet, and fetch for the network" widths={[800, 1600]} sizes="(min-width: 768px) 720px, 100vw" />

## A typed effects chain

Each of the 86 effects is an FFmpeg filter with typed options: equalizers, compressors and limiters, loudness
normalisation, pitch and tempo, stereo width, crossfeed and more, applied in list order. Changing only an
effect's parameters is applied to the running graph in place, with no audible rebuild, and a tap can read the
signal after any stage.

```dart
await player.setAudioEffects(const [
  EqualizerEffect(frequency: 100, width: 50, widthType: EqualizerWidthType.h, gain: 3),
  LoudnormEffect(i: -16),
  AlimiterEffect(limit: 0.9),
]);
```

## Live PCM input

A `PcmSource` plays raw PCM chunks while they arrive, such as speech generated piece by piece or samples sent over
a socket. There's no file, no local server and no header: the chunks go straight to mpv through a `mak-pcm`
protocol patched into it, and playback starts about 0.2 s after the first one.

```dart
final source = await player.openPcmStream(
  const PcmFormat(sampleRate: 24000, channels: 1), // s16le by default
);
await source.addStream(chunks);
await source.close(); // plays out what's buffered, then ends the entry
```

## URLs that expire

A source resolver gives each entry its stream URL when it opens, prefetch included, so the tokens in a long
queue never go stale, and an open that fails gets one retry with a fresh URL.

```dart
await player.setSourceResolver((request) async {
  final id = request.media.extras?['trackId'] as String?;
  return id == null ? null : api.streamUrl(id); // null keeps the URL
});
```

## Streams, network and TLS

HTTP(S), HLS, DASH and SMB2/3 play like local files, with control over the cache, timeouts, proxies and
reconnects. Since 0.8.0 TLS certificates are verified by default, as in mpv and FFmpeg; a home server with a
self-signed certificate is trusted on top of the built-in roots with `setTlsExtraCaFile`, while every other server
is still checked.
