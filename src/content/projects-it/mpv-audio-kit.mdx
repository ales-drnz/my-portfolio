## Perché l'ho creato

Molte librerie audio per Flutter si basano su una vecchia versione di mpv, o ne nascondono l'elaborazione audio.
mpv_audio_kit espone tutto il motore tramite un'API Dart tipizzata, senza bloccare l'interfaccia, per le app che
riproducono una libreria multimediale:

- **Jellyfin**: stream diretti o transcodificati, e l'HLS transcodificato resta navigabile mentre il server
  converte.
- **Plex**: brani e playlist via HLS o DASH; ogni voce chiede lo stream al server solo quando si apre, così una
  coda lunga parte subito.
- **Samba**: riproduzione direttamente da un NAS o da una qualsiasi condivisione di rete via SMB2 e SMB3.

Il progetto è diviso in tre repository:

- **mpv_audio_kit**: il pacchetto Dart e Flutter, pubblicato su pub.dev.
- **[libmpv-scripts](https://github.com/ales-drnz/libmpv-scripts)**: mpv e FFmpeg compilati senza video, con le
  patch su cui si basa il pacchetto (forma d'onda, analisi della loudness, tap audio, PCM in tempo reale), per ogni
  piattaforma su cui gira, da un menu da terminale scritto in Go.
- **[MPV Studio](/it/projects/mpv-studio)**: l'app di riferimento costruita sul pacchetto, che gira anche
  [nel browser](https://ales-drnz.github.io/mpv_studio/).

## Per iniziare

```yaml
dependencies:
  mpv_audio_kit: ^0.8.0
```

```dart
void main() {
  WidgetsFlutterBinding.ensureInitialized();
  MpvAudioKit.ensureInitialized();
  runApp(const MyApp());
}

// poi, nell'app
final player = Player();
await player.open(Media('https://example.com/audio.flac'));
await player.play();
player.stream.position.listen((position) => print(position));
await player.dispose(); // quando hai finito
```

`player.state` contiene i valori attuali e `player.stream` invia ogni cambiamento.

## Architettura

Il `Player` vive sull'isolate principale e chiama libmpv senza aspettarlo. Un isolate in background resta in
attesa su `mpv_wait_event` e riporta lo stato, così gli stream di rete lenti e i grafi di filtri pesanti non
bloccano mai l'interfaccia. Sul web è invece il modulo a risvegliare il player sul thread principale.

<Image src={architecture} alt="Architettura: la tua UI e il Player sull'isolate principale, l'isolate degli eventi, libmpv sui thread nativi con mpv 0.42 e FFmpeg, e il plugin di piattaforma verso i controlli multimediali di sistema" widths={[800, 1600]} sizes="(min-width: 768px) 720px, 100vw" />

Anche la media session è pilotata da Dart: la notifica multimediale su Android, Now Playing su Apple, MPRIS su
Linux, i controlli multimediali su Windows e AVSession su HarmonyOS, ovunque tranne su Tizen e webOS. Su Android e
HarmonyOS tiene anche l'app in riproduzione in background.

## Dodici piattaforme

Android, iOS, macOS, Windows e Linux; Android TV, tvOS, Tizen e webOS sulle TV; Wear OS sugli smartwatch;
HarmonyOS; e il browser. Un build hook di Dart scarica la build di libmpv per ogni target nativo dalle release del
progetto e la verifica rispetto a uno SHA-256 fissato. I toolchain che non eseguono build hook la ricevono in un
altro modo: Swift Package Manager su tvOS, CMake su webOS, e sul web il modulo è incluso nel pacchetto.

## Nel browser

Sul web mpv e FFmpeg girano come un unico modulo WebAssembly, con i thread di libmpv nei web worker, le letture di
rete passano da `fetch` e il suono esce da un AudioWorklet alimentato da un buffer circolare in memoria condivisa.
La pagina deve essere cross-origin isolated, e serve un gesto dell'utente per avviare l'audio.
[MPV Studio](https://ales-drnz.github.io/mpv_studio/) gira così, l'intera app in una scheda del browser.

## Una catena di effetti tipizzata

Ognuno degli 86 effetti è un filtro FFmpeg con opzioni tipizzate: equalizzatori, compressori e limiter,
normalizzazione della loudness, pitch e tempo, ampiezza stereo, crossfeed e altro, applicati nell'ordine della
lista. Cambiare solo i parametri di un effetto si applica al grafo in esecuzione, senza una ricostruzione
udibile, e un tap può leggere il segnale dopo qualsiasi stadio.

```dart
await player.setAudioEffects(const [
  EqualizerEffect(frequency: 100, width: 50, widthType: EqualizerWidthType.h, gain: 3),
  LoudnormEffect(i: -16),
  AlimiterEffect(limit: 0.9),
]);
```

## Input PCM in tempo reale

Un `PcmSource` riproduce blocchi di PCM grezzo man mano che arrivano, come il parlato generato a pezzi o i campioni
inviati su un socket. Niente file, niente server locale e niente header: i blocchi vanno direttamente a mpv tramite
un protocollo `mak-pcm` aggiunto con una patch, e la riproduzione parte circa 0,2 s dopo il primo.

```dart
final source = await player.openPcmStream(
  const PcmFormat(sampleRate: 24000, channels: 1), // s16le di default
);
await source.addStream(chunks);
await source.close(); // riproduce quello che è nel buffer, poi chiude la voce
```

## URL che scadono

Un source resolver dà a ogni voce il suo URL di stream quando si apre, prefetch compreso, così i token di una coda
lunga non scadono mai, e un'apertura fallita ha un nuovo tentativo con un URL nuovo.

```dart
await player.setSourceResolver((request) async {
  final id = request.media.extras?['trackId'] as String?;
  return id == null ? null : api.streamUrl(id); // null mantiene l'URL
});
```

## Stream, rete e TLS

HTTP(S), HLS, DASH e SMB2/3 si riproducono come file locali, con il controllo di cache, timeout, proxy e
riconnessioni. Dalla 0.8.0 i certificati TLS sono verificati di default, come in mpv e FFmpeg; un server di casa con
un certificato autofirmato si aggiunge alle radici incluse con `setTlsExtraCaFile`, mentre tutti gli altri server
restano verificati.
